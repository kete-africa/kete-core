# Contracts

The source of truth for every exchange between Kete services. TypeScript types in
`packages/sdk/src/contracts/` are generated from these files (`pnpm contracts:generate`); CI fails
if the generated code no longer matches (`pnpm contracts:check`).

| File                                | Contract                                                                                                                                                                                                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `event.v1.schema.json`              | The integration event envelope, naming the object it is about (spec 143)                                                                                                                                                                                                     |
| `event-data.v1.schema.json`         | The `data` of each standard event type                                                                                                                                                                                                                                       |
| `delivery-request.v1.schema.json`   | A signed batch of events sent to a receiver                                                                                                                                                                                                                                  |
| `delivery-result.v1.schema.json`    | The receiver's outcome for each event                                                                                                                                                                                                                                        |
| `manifest.v1.schema.json`           | An app's self-description (`kete.json`, `GET /.well-known/kete`), with its identity card: owner, data categories, AI use, criticality (D-040); its permissions, events emitted, decision subjects and client id (spec 049); since spec 099, its question, places and metrics |
| `health.v1.schema.json`             | An app's health report (`GET /health`)                                                                                                                                                                                                                                       |
| `capability.v1.schema.json`         | What an app exposes to agents, with its autonomy level (1 to 4)                                                                                                                                                                                                              |
| `dataset.v1.schema.json`            | A set of rows an app exposes to dashboards, the assistant and other apps, under the reader's rights; since spec 144, the fields carrying the four axes                                                                                                                       |
| `dataset-query.v1.schema.json`      | A question put to a data set — axes, own fields, groups, measures, period — summed up at the app (spec 144, ADR 0015)                                                                                                                                                        |
| `dataset-answer.v1.schema.json`     | The answer to it: the groups and their measures, the rows counted, the axes applied; never the rows (spec 144)                                                                                                                                                               |
| `money-fact.v1.schema.json`         | A fact of money an app says to its center — invoiced, received, committed, spent — with its amount in the smallest unit, its project, its budget post and its third party                                                                                                    |
| `dated-fact.v1.schema.json`         | Something that will happen at a time — a meeting, a deadline, an absence, a task, a milestone, an agent's run — said to the center's Planifier, on a day or at a moment, with its people, project and visibility (D-050)                                                     |
| `holding.v1.schema.json`            | A thing in progress and who holds it — a request, a circuit step, a draft, an agent's task — never without a holder, said by an app under its source (D-056)                                                                                                                 |
| `gesture.v1.schema.json`            | A gesture about to be made by a person or an agent acting for one — who, what, on what, how much, which channel, towards whom — read by the policy engine (D-058)                                                                                                            |
| `policy.v1.schema.json`             | A rule of the organization: its sentence, its Cedar rule, authority or approval, its approver, its owner, its version, active, on trial or off (D-058)                                                                                                                       |
| `policy-decision.v1.schema.json`    | What the policy engine decided for a gesture — allow, approve, refuse — with the policies, versions and reasons, and what the policies on trial would have said (D-058)                                                                                                      |
| `thread.v1.schema.json`             | Where people talk about one thing — born with its object, a group, a direct exchange, a person's thread with Kete — with its holder, its members since when, its address for replies by mail (D-057)                                                                         |
| `message.v1.schema.json`            | One thing said in a thread by a person, an agent or a contact through a channel; never rewritten, an edit names what it replaces; « for action » becomes a holding (D-057)                                                                                                   |
| `routing.v1.schema.json`            | Where the router tied something received from outside — object, thread, holding — by a rule, by the model's intent with its confidence, or by a person on a card « à classer » (D-056)                                                                                       |
| `object-type.v1.schema.json`        | A kind of object an app (in its manifest's `objects`) or the center declares once: its states, which of the four axes it carries, its named links, where one opens (D-062, spec 142)                                                                                         |
| `object.v1.schema.json`             | One object said to the center's index — title, state, the four axes, named links, where it opens — never its data; said again it replaces, `gone` takes it out (spec 142)                                                                                                    |
| `view.v1.schema.json`               | A generic component configured where it is used — card, collection, figure, board, form, timeline —, its source, context, filters, gestures and its kind's options; data, never code (spec 145, ADR 0016)                                                                    |
| `metric.v1.schema.json`             | A figure an app declares in its manifest, computed by its code, with its unit, whether up is good, and its axes — the center's references (D-052)                                                                                                                            |
| `proposal-set.v1.schema.json`       | Several proposals — the evening's tidying, a plan — decided together by one gesture, each with the level of the gesture that applies it (D-051)                                                                                                                              |
| `resource.v1.schema.json`           | A skill, an agent or an app in its lifecycle: owner, version, tier, review by its risk, test cases passed (D-053)                                                                                                                                                            |
| `lesson.v1.schema.json`             | What the use of a resource taught, gathered with consent, kept (a test case) or dropped by its owner (D-053)                                                                                                                                                                 |
| `file-link.v1.schema.json`          | A file an app keeps, said to the center with the object it proves, its role, nature and origin                                                                                                                                                                               |
| `intelligence-event.v1.schema.json` | One event of a Kete Intelligence turn — status, plan, step, tool with its level, draft, source, text, wait, end, failure — the same stream in the center and every app                                                                                                       |

Signature headers (outside the JSON body): `Kete-Product: <product id>` and
`Kete-Signature: t=<unix seconds>,kid=<key id>,v1=<hex HMAC-SHA256 of "{t}.{raw body}">`.

## Versioning rules

- Within a major version, changes are **additive only**: a new optional field, a new standard
  event type, a new refusal reason.
- Removing, renaming or restricting a field requires a **new major version** (`event.v2`), in a new
  file.
- During a transition, receivers accept the previous major version until every emitter has moved.
