## 1. Summary

1. **Sound modules, missing links.** R4, R9, R16, R19 hold; R1, R2, R3, R5, R7, R8, R11, R14, R15, R21, R22 do not.
2. **Agents get a fraction of Kete's tools.** Three tool assemblies: the drawer (`ent:assistant/assistant.ts:963-979`,
   apps + skills + library + data), Kete's thread (`ent:messages/door.ts:553`), an agent's task
   (`ent:agents/tasks.ts:757-794`). The gateway gives MCP and agents **10 capabilities for 48 features**
   (`ent:gateway/capabilities.ts:27-189`): no holdings, threads, money, time, meetings, compliance, library.
3. **Events reach almost no one.** One listener, the routines (`ent:apps/events.ts:104` → `ent:routines/runs.ts:220`);
   live = threads only; holdings, agents, watches, schedules are polled (14 jobs in `apps/api/src/worker.ts`).
4. **Four figure systems, unconnected:** Performance's free-text `source` (`ent:performance/infrastructure/performance.tables.ts:34`),
   dashboards over uploaded tables and forms only, aggregated in memory up to 50 000 rows (`ent:datasets/routes.ts:33`),
   `@kete/metrics`/`@kete/boards` with no product consumer, apps' datasets without axes, never read by the center.
5. **Axes are rare:** 8 of ≈ 115 center tables carry a project or party; actions, meetings, compliance, agents,
   dashboards, requests none; Support's tickets none (`hd:…/ticket.table.ts:22-42`); `metric.v1` has no `unit`.
6. **The apps lag the core:** all pin `@kete/sdk ^0.7.0` (older than manifest `places`/`metrics`, sdk 0.8.0); none
   declares places, metrics, objects, watches, agents; none wears `@kete/shell`/`@kete/intelligence`; Support has
   no assistant; Kete Enterprise's manifest declares nothing (`apps/api/kete.json:5`).
7. **Dead paths:** `center.sendDatedFact`/`sendTask` called by no app — leaves, obligations, due dates never reach
   Planifier nor the holdings relay.
8. **Doubtful today (no consumer):** `@kete/metering`, `@kete/connections`, `@kete/lifecycle`, `@kete/boards`;
   `@kete/metrics` (template only); `evaluateAgent`.
9. **Duplicates:** lifecycle ≈ Enterprise `registry`; metering ≈ `@kete/ai` usage; connections ≈ 4 Enterprise
   credential stores (3 AES-GCM codes); `assistant_memories` ≈ `@kete/agents` memory; `rules` ≈ `policies`; four
   AI schedulers; `actions` ≈ `corrective_actions`; `app_tasks` ≈ holdings; `forms` ≈ `surveys`; `dossiers` ≈ object space.
10. **Object life:** app objects get a thread only when a screen opens them (never via MCP); `closeThread` is never
    called (`core:threads/src/threads.ts:255`): a closed project keeps its thread open.

## 3. Per rule

### R1 — The object at the center

- **Holds:** projects and parties are center objects with a thread born with them
  (`ent:messages/objects.ts:18-33`); `thread.v1`, `holding.v1`, `file-link.v1`, `gesture.v1` name
  `object {kind, id}`; `@kete/channels` routes to an object (`core:channels/src/migration.ts:35-63`).
- **Broken:** no object index or type registry at HEAD (spec 142 uncommitted). Actions, decisions,
  meetings, compliance findings, colleague requests, app requests, forms' submissions, documents
  produced are rows without object identity or thread. Apps' objects get a thread only through a
  screen's server function (`fin:src/features/sales/functions.ts:51`,
  `com:src/features/contracts/functions.ts:69-78`, `team:src/features/time/functions.ts:87-92`):
  an object created by an agent through MCP has none. Finance's purchases, Commitments'
  obligations and securities, Team's authorisations have no thread at all.

### R2 — Four axes, everywhere

- **Holds:** `money_facts` and `time_facts` carry project and party (`ent:money/money.ts:17`,
  `ent:time/time.ts:15`); Finance and Commitments rows carry both.
- **Broken:** of the center's ≈ 115 tables, project or party columns appear on 8 only
  (`projects`, `project_posts`, `parties`, `party_facts`, `money_facts`, `time_facts`,
  `thread_objects`, plus `decision_requests.project_id` at
  `ent:decisions/infrastructure/decisions.tables.ts:120`). `actions`, `meetings`, `compliance`,
  `agents`, `colleague_requests`, `app_tasks`, `dashboards`, `team_datasets`, `form_collections`
  carry none. Support's tickets carry none. `metric.v1` lacks `unit` (`ctr:metric.v1.schema.json:47`);
  `dataset.v1` lacks `axes`; `holding.v1` has an object but no axes. Dashboards filter by a free
  column name (`ent:dashboards/routes.ts:119-127`) — « filter by project » needs code per source.

### R3 — Declared once, served everywhere

- **Holds:** capabilities and datasets are declared once and described in the manifest
  (`core:capabilities/src/datasets.ts:64`); the center reads apps' identity cards (`ent:apps`).
- **Broken:** the four apps' manifests declare `capabilities`, `datasets`, `permissions`,
  `subjects`, `emits` only (`fin:src/platform/events.ts:53-76`, same in the three others) — no
  `places`, `metrics`, `question`, and they cannot: `@kete/sdk ^0.7.0` predates them (sdk
  CHANGELOG 0.8.0). Kete Enterprise declares nothing (`kete-enterprise/apps/api/kete.json:5`).
  Each consumer keeps its own list: the drawer (`ent:assistant/assistant.ts:963-979`), Kete's
  thread (`ent:messages/door.ts:553`), agents (`ent:agents/tasks.ts:757-794`), MCP
  (`ent:gateway/mcp.ts:53-60`), watches (`ent:agents/watches.ts:23`, a code registry).

### R4 — The same rights everywhere

- **Holds:** the gateway, agents and the drawer run as the person (`asPerson`,
  `ent:agents/tasks.ts:744`); dashboards and datasets read with the reader's rights
  (`ent:dashboards/routes.ts:167`); policies decide the same for a person and her agent
  (`core:policies`); apps answer with the person's token (`core:center`).
- **Gap:** rights on the object axis exist only for projects (team) and dossiers (members); there
  is nothing to apply them to other objects until the index exists (0014).

### R5 — An agent is Kete narrowed to a job description
