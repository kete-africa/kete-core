# Security review — 2026-10-18 (phase 11, step E4)

On the author's word (« E4 : d'accord »). Scope: what reached `dev` in phase 11 and opens Kete to the
outside — imported tools, the agents' abilities (web, computer, sub-agents), the fleet's API, the
provisioning port, the test mailbox — and the dependencies. Method: reading the code paths that
cross a trust boundary, then a test for each fix. Spec 134 carries the fixes.

## Fixed (spec 134)

| #   | Finding                                                                  | Risk                                                                                                                                                                                          | Fix                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | `publicFetch` checked a name's addresses, then `fetch` resolved it again | DNS rebinding: a name answers « public » to the check, « private » to the connection — the instance's network reached through an imported tool or a page read                                 | The address is checked again **at connection time** (`publicLookup` in an `undici` agent); the body is cut once beyond 2 MB even without `Content-Length`                                                                                        |
| 2   | After outside content, only level 2 gestures waited                      | Exfiltration: a page or a message carrying instructions makes the agent send the organization's data out — through its computer (it has the network) or an address it makes up for `web_read` | Once outside content is in a turn, `computer_run` and `computer_write` wait for a person, and `web_read` reads only an address the outside content gave (a search's source) — in `runAgent` and `guardOutside` alike; sub-agents share the watch |

## Checked, holds

- **Organizations stay apart**: every table under row-level security in the same migration; the
  application roles cannot bypass it (`rls-audit.test.ts` in the Compte Kete).
- **Secrets**: sealed with AES-256-GCM (connections, imported tools' keys, Enterprise's keys), never
  returned by an API, kept out of the journal (`journalInput: false`).
- **Agents never exceed their person**: every capability authorized for the person the agent acts
  for; imported tools under `tools:read` and `tools:act`; acts are drafts, destructions need a
  confirmation; the organization's policies are asked before each tool, abilities included.
- **Kete's names cannot be shadowed** by an imported tool; a registry MCP server that is not a Kete
  app lends only its read-only tools.
- **The fleet API** (`/api/admin/deployments`) and the test mailbox answer only Kete's operators
  (owners or administrators of Kete's organization, second factor on); the test mailbox never in
  production.
- **The provisioning port**: names checked before reaching SQL; database addresses never printed;
  a failed step undone.

## Dependencies

`pnpm audit`: no high or critical advisory outside the two the repository already ignores (with
their reason in `package.json`); three moderate and one low, in development tools (`esbuild` under
`drizzle-kit`) and in `@mastra/core`'s YAML parser — none on a path reached by a request.

## Open — recommended next

- Kete Enterprise keeps its own copy of the public-internet guard (`features/tools`): it moves to
  `@kete/tools`' `publicFetch` once released, to get fix 1.
- Rate limits on the agents' web and computer use per person and day, beyond the token budgets.
- An external penetration test before production (E4), on the staging instance.
- Rotating the staging secrets that were shared in this phase's sessions, before production.
